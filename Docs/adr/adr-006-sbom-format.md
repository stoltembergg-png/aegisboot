# ADR-006: SBOM and Provenance Format

## Status
Accepted

## Context
Supply chain security requires verifiable artifacts. Every release must include a Software Bill of Materials (SBOM) and SLSA provenance statement.

## Decision
**SBOM Format:** CycloneDX 1.5 JSON
- Generated by `syft` from built artifacts in `Binaries/`
- Includes all packages, dependencies, licenses
- Validated by `scripts/validate_sbom.py`

**Provenance Format:** SLSA Level 3 Provenance (in-toto Statement v0.1)
- Generated by `scripts/generate-provenance.py`
- Includes: build config, materials, artifacts with SHA256/SHA512, reproducibility metadata
- Builder: GitHub Actions runner (id: `https://github.com/actions/runner`)
- Build config: workflow file, external parameters (tag, upstream_version, revision)

**Artifact Hashes:**
- SHA256 and SHA512 for all zip files
- SHA256 and SHA512 for distro-version.json, checksums, SBOM, provenance
- Generated by `scripts/verify-distro.sh`

**Release Artifacts Checklist:**
- [ ] Binary zips (RELEASE, DEBUG, NOOPT)
- [ ] distro-version.json
- [ ] SHA256SUMS.txt
- [ ] SHA512SUMS.txt
- [ ] OpenCorePkg-cyclonedx.json
- [ ] provenance.json

## Consequences
**Positive:**
- Full supply chain traceability
- SLSA Level 3 compliance
- Automated generation and validation
- Machine-readable and human-auditable

**Negative:**
- Requires `syft` installation in CI
- Provenance generation adds build time
- SBOM size can be large
